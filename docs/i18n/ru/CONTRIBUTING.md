## Локальная разработка

Требуются Node.js >=22.12.0 и pnpm 12.5.1. Версия менеджера пакетов закреплена в поле packageManager файла package.json.

```sh
pnpm install --frozen-lockfile
pnpm prepare:test-project
pnpm --dir test-project dev
```

Проект-потребитель устанавливает библиотеку из настоящего tarball-архива. После изменения библиотеки снова выполните `pnpm prepare:test-project`. Сохраняйте этот процесс работы через пакет, не вводя псевдонимы исходного кода. Не добавляйте в коммиты артефакты, node_modules и журналы выполнения.

## Проверка

```sh
pnpm typecheck
pnpm test
pnpm prepare:test-project
pnpm --dir test-project build
pnpm exec playwright install chromium
pnpm test:e2e
```

CI выполняет эти проверки в Linux. Браузерные тесты автоматически используют порт 4174; демо для разработки использует порт 4173.

## Каталоги

- `src/components`: семь компонентов и их публичные типы.
- `src/core`: конфигурация, провайдеры, запросы и общие типы.
- `src/adapters`: необязательный адаптер XLSX.
- `src/styles`: явно импортируемые стили компонентов.
- `tests`: модульные тесты и негативные тесты типов.
- `test-project`: самостоятельный проект-потребитель и тесты взаимодействий в Chromium.
- `scripts`: скрипты упаковки и настройки проекта-потребителя.

## Pull Requests

Опишите проблему, итоговое поведение и проверки, которые вы действительно выполнили. Исправляя ошибку компонента, добавьте регрессионный тест, воспроизводящий проблему. Обновляйте документацию при изменении публичных API или способов использования. Сосредоточьтесь на нужных изменениях и избегайте не связанного с задачей форматирования всего репозитория.

Следуйте существующим строгим настройкам TypeScript и стилю кода. React 19 остаётся peer-зависимостью, стили используют отдельную точку входа, а XLSX не включается в основную точку входа. Вклады предоставляются на условиях лицензии MIT этого репозитория.

## Переводы документации

Английские документы используют свои имена файлов по умолчанию. Переводы сгруппированы по локалям в каталоге `docs/i18n/<locale>/`, например `docs/i18n/ja/README.md` и `docs/i18n/zh-CN/migration.md`. Сохраняйте одинаковые разделы, примеры, технический смысл и статус релиза во всех языках. Сохраняйте публичные идентификаторы и аргументы команд без изменений. При обновлении документа обновляйте его переводы и поддерживайте согласованность ссылок переключения языка и ссылок на связанные документы.
