## Учётные записи и имя пакета

GitHub-репозиторий: `Zeroman/react-auto-components`. Учётная запись npm — `zeroman.yang`. Скоуп `@zeroman` принадлежит другому пользователю npm, поэтому имя пакета — `@zeroman.yang/react-auto-components`.

1. Откройте [страницу регистрации npm](https://www.npmjs.com/signup), введите имя пользователя, электронную почту и пароль, лично ознакомьтесь с условиями и примите их.
2. Подтвердите электронную почту из регистрационного письма. npm требует подтверждённый адрес перед публикацией; адреса издателей отображаются в метаданных пакета, поэтому выберите адрес, подходящий для публичного сопровождения.
3. Включите двухфакторную аутентификацию в настройках учётной записи и сохраните данные восстановления. Никогда не помещайте пароли, коды подтверждения, коды восстановления и токены в репозиторий или чат.
4. Выполните `npm login --registry=https://registry.npmjs.org/` и следуйте инструкциям в браузере. Проверьте учётную запись командой `npm whoami --registry=https://registry.npmjs.org/`.
5. Рекомендуется личная область имён, например `@<npm-username>/react-auto-components`. Для области организации сначала проверьте членство и права публикации.

После окончательного выбора имени обновите имя в корневом package.json, импорты во всех переводах README, зависимости проекта-потребителя и импорты в исходном коде и тестах. Затем выполните `pnpm prepare:test-project`, чтобы обновить файл блокировки зависимостей потребителя. Скрипт упаковки выводит имена tarball-архивов из корневого package.json.

Официальная документация: [регистрация учётной записи](https://docs.npmjs.com/creating-a-new-npm-user-account/), [публичные пакеты с областью имён](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages/) и [двухфакторная аутентификация](https://docs.npmjs.com/about-two-factor-authentication/).

## Проверка перед выпуском

Выполните из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm prepare:test-project
pnpm --dir test-project build
pnpm exec playwright install chromium
pnpm test:e2e
npm pack --dry-run
```

`prepack` автоматически собирает JavaScript, CSS и декларации; `prepublishOnly` запускает проверки типов и модульные тесты. Пакет npm содержит только dist, README и переводы README и руководства по миграции, LICENSE и package.json. Убедитесь, что учётные данные, локальные журналы и результаты тестов исключены. Остальная документация репозитория доступна по ссылкам на GitHub.

`test-project` проверяет реальные публичные точки входа через tarball-архив с хешем содержимого. После свежего клонирования выполните `pnpm prepare:test-project` из корня до установки зависимостей в этом каталоге. Команда подготовки обновляет локальную зависимость потребителя и его файл блокировки.

## Первый выпуск

Когда завершены настройка учётной записи, выбор окончательного имени пакета, подготовка лицензии и проверки выше:

```sh
npm whoami --registry=https://registry.npmjs.org/
npm publish --access public --registry=https://registry.npmjs.org/
```

Пройдите все проверки, запрошенные npm. После публикации выполните `npm view <package-name> version` с окончательным именем, затем установите и проверьте пакет в новом проекте-потребителе. После успешного первого выпуска удалите уведомление о его подготовке из каждого перевода README и добавьте инструкции по установке.

Перед каждым выпуском обновляйте версию и все переводы CHANGELOG. Не пытайтесь перезаписать опубликованную версию. Отправьте тег `v*`, совпадающий с версией в `package.json`, например `v0.2.0` для версии `0.2.0`. Это запускает `.github/workflows/publish.yml` и публикует пакет в npm.

## Автоматизированные выпуски

[npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/) связывает `@zeroman.yang/react-auto-components` с репозиторием GitHub `Zeroman/react-auto-components` и файлом рабочего процесса `publish.yml`. Процесс использует раннер GitHub и OIDC `id-token: write`, без долгоживущего токена npm. Требуются Node >=22.14.0 и npm CLI >=11.5.1. Тег, версия `package.json` и проверенный коммит должны совпадать.

GitHub Actions CI устанавливает зависимости по файлу блокировки, проверяет типы, запускает модульные тесты, собирает потребительский проект с настоящим tarball-архивом и запускает тесты Chromium. Защита веток может требовать успешного CI перед слиянием; настраивайте её по мере изменения потребностей сопровождения при появлении внешних участников.
